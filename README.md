# Kulot Friends Chat

A small invite-only website for one group of friends. It includes:

- Registration protected by one private invite code
- Login and logout
- Automatic access to the one shared chat after registration
- Messenger-style shared conversation for every registered user
- Online/offline member list
- Incoming group-call prompt with Accept and Decline
- Group voice and video calling with WebRTC
- Microphone mute, camera toggle, and leave-call controls
- SQLite message history

## 1. Run on Windows PowerShell

Open PowerShell inside this project folder:

```powershell
py -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Change these values in `.env`:

```env
SECRET_KEY=put-a-long-random-secret-here
INVITE_CODE=your-private-code-for-friends
COOKIE_SECURE=false
```

Start the website:

```powershell
python app.py
```

Open:

```text
http://127.0.0.1:5000
```

Each friend registers using the invite code and is signed in automatically. Every registered account opens the same shared conversation; there is no separate group-selection or join-group step.

## 2. Test with two accounts

Use two different browsers, such as Edge and Chrome, or one normal window and one private window.

1. Register two usernames with the invite code. Registration opens the chat automatically.
2. Send messages from both accounts.
3. Press the phone or video icon in one browser.
4. Accept the incoming group call in the other browser.
5. Allow microphone and camera access.

Camera and microphone access works on `localhost`. Browsers normally require HTTPS when the website is opened from a public domain or a different device.

## 3. Put it on GitHub

Create an empty GitHub repository, then run:

```powershell
git init
git add .
git commit -m "Initial friends chat"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

The `.env` file and local database are ignored and will not be uploaded.

## 4. Deploy to Render

1. On Render, choose **New → Blueprint** or **New → Web Service**.
2. Connect the GitHub repository.
3. Render can read `render.yaml` automatically.
4. Set `INVITE_CODE` to a private code in Render's environment settings.
5. `SECRET_KEY` is generated by the blueprint.
6. Deploy.

Manual settings:

```text
Build command: pip install -r requirements.txt
Start command: gunicorn -w 1 --threads 100 app:app
```

Your public website will receive an HTTPS address similar to:

```text
https://kulot-friends-chat.onrender.com
```

## Important cloud limitations

### SQLite storage

SQLite is perfect for local testing. On cloud services with an ephemeral filesystem, message history can disappear after a restart or redeployment. For permanent history, attach persistent storage and set:

```env
DATABASE_PATH=/var/data/friends.db
```

Or replace SQLite with PostgreSQL later.

### Voice/video connectivity

This starter uses a peer-to-peer mesh. It is suitable for a small group, roughly 2–5 active callers. The included public STUN server is often enough, but calls can fail on restrictive mobile networks, carrier-grade NAT, school Wi-Fi, or corporate Wi-Fi.

For reliable public calling, configure a TURN server through `ICE_SERVERS_JSON`, or later replace the call layer with LiveKit Cloud. Example structure:

```env
ICE_SERVERS_JSON=[{"urls":"stun:stun.example.com:3478"},{"urls":"turn:turn.example.com:3478","username":"temporary-user","credential":"temporary-password"}]
```

Do not commit private long-term credentials to GitHub.

## Production checklist

- Replace the default invite code.
- Use a long random `SECRET_KEY`.
- Set `COOKIE_SECURE=true` on HTTPS hosting.
- Keep one Gunicorn worker for this in-memory Socket.IO starter.
- Add a TURN server for reliable calls across different networks.
- Use persistent storage or PostgreSQL before relying on message history.
- Add account administration before sharing beyond close friends.
